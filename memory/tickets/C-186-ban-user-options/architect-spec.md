# C-186 — Архитектор: варианты блокировки человека на всём Кампусе

**P1** · W-60 · proposal only (без кода в этой волне, пока Клиент не выберет)

## Контекст

Сейчас есть: host kick из комнаты, Trust Score, auto-restrict после 3 жалоб, Owner Inbox.  
Нет: «этот человек больше не заходит ни в одну комнату».

Идентификатор сегодня — анонимный `client_id` в localStorage (+ IP в audit). Без VK/телефона бан легко обойти очисткой браузера / VPN.

---

## Вариант A — Бан по client_id + IP (быстрый MVP)

**Как:** в кабинете владельца кнопка «Заблокировать» у жалобы → запись в `bans.jsonl` (`client_id`, `ip`, `until`, `reason`).  
`GET /token` и join отдают **403 banned**, если совпал client_id или недавний IP.

| Плюсы | Минусы |
|-------|--------|
| 1–2 дня работы | Обходится сменой браузера / VPN |
| Уже есть client_id | Ложные срабатывания по общему Wi‑Fi (офис, кафе) |

**Рекомендуется как первая ступень.**

---

## Вариант B — Бан + «отпечаток» устройства (усиление A)

**Как:** лёгкий fingerprint (не cookie) + client_id + IP. Бан матчится по любому из трёх.

| Плюсы | Минусы |
|-------|--------|
| Сложнее обойти | Privacy / 152‑ФЗ осторожность; fingerprint не 100% |

---

## Вариант C — Обязательный вход (VK ID / телефон РФ) + бан аккаунта

**Как:** по 406‑ФЗ — VK ID / Яндекс / SMS. Бан привязан к стабильному `user_id` провайдера.

| Плюсы | Минусы |
|-------|--------|
| Настоящая юридическая и техническая блокировка | Большой продукт + UX; нужен выбор провайдера |

**Целевой контур «как у взрослых платформ».**

---

## Вариант D — Только ручной Owner + Trust gate (без hard ban)

Снижать Trust до 0 → закрыть все комнаты с порогом; kick везде через LiveKit RoomService.

| Плюсы | Минусы |
|-------|--------|
| Почти уже есть | Не «бан сайта», а «не пускаем в комнаты с порогом» |

---

## Рекомендация Архитектора

1. **Сейчас (до деплоя сайта):** внедрить **вариант A** (Owner Inbox → ban client_id/IP, gate на token).  
2. **Параллельно в roadmap:** **вариант C** (VK ID) — закрывает и 406‑ФЗ, и устойчивый бан.  
3. Вариант B — опционально между A и C.

Нужен выбор Клиента: `A` / `A+B` / сразу проектировать `C`.
