# Capacity decision brief — Vernatun Lounge (C-160)

Дата: 2026-09-25. Ориентир, не промышленный load-test.
База: `liverooms/LOAD_CAPACITY.md` + типичный VPS `155.212.187.181` (LiveKit + lounge_api + coturn).

## Сколько «потянуть» комнат по ~10 человек

При mute-by-default (говорят 2–4 одновременно в комнате):

| Режим | Комнат × 10 чел | Одновременных голосов | Вердикт |
|-------|-----------------|------------------------|---------|
| Комфорт сейчас | **6–8** | ≤25–30 publish | спокойно для клуба |
| Осторожный потолок | **10** | ≤35–40 | следить CPU / packet loss |
| Рискованно без апгрейда | **15+** | 50+ | нужен отдельный SFU/железо |

Сайт (Vite static) почти не ограничивает. Узкое место — **LiveKit SFU + UDP/TURN**, не React.

## Решение: что выбрать сейчас

### Рекомендация команды: **сначала ~10 базовых комнат**, права ведущего — **первому вошедшему** (уже так в token API).

**Почему не «все сами создают» прямо сейчас**
1. Самосоздание без лимита легко упрётся в SFU (20 «пустых» комнат хуже, чем 10 живых).
2. Нужны квоты, антиспам, пароли, чистка — это отдельная волна.
3. У вас уже есть каталог уровней (A1/B1/…) + создание воркшопа с паролем — этого хватает для пилота.

**Когда включать свободное создание**
- Grafana стабильна на 10×10 в пиковые вечера 2 недели
- Жёсткий лимит: max 10–12 *активных* комнат одновременно (создание в лобби → «ждите / займите свободную»)
- Квота: 1 комната на создателя / час

## Простыми словами для решения владельца

- **10 готовых комнат** = как 10 столов в кафе: предсказуемо, ведущий — кто сел первым.
- **Свободное создание** = каждый тащит свой стол: удобно друзьям, но сервер может «захлебнуться», если все создадут сразу.

**Предложение:** оставить **базовые ~10 + редкое «создать с паролем»**, не открывать бесконечное создание, пока не измерим вечерний пик на VPS.
