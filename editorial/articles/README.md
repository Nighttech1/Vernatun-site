# Редакция статей Вернатуна

Решение Алика от 19.11.2026. Ответственная: штатная арт-сценаристка и SEO-редактор клуба. Задача: полезные, красивые статьи об армянском языке, культуре, встречах и сообществе Москвы, с осмысленными фотографиями и видео.

## Где работаем

- Вся редакционная работа: `editorial/articles/`. Правила: [RULES.md](RULES.md), источники: [sources.md](sources.md), темы: [PLAN.md](PLAN.md).
- Каждый материал: `drafts/<slug>/article.md`, `research.md`, `media.json`, `bot-handoff.json`. Черновики и журналы согласования не помещать в публичный `articles/`.
- Публикуемый источник остаётся `content/articles/<slug>.md`, HTML в `articles/` генерируется существующим движком. Второго генератора не создаём.
- [INTEGRATION.md](INTEGRATION.md) описывает ограничения и следующие действия. [news/2026-11-19.md](news/2026-11-19.md) начинает редакционный радар.

## Порядок работы

Исследование → полный текст и медиаплан → редакционная проверка → версия на согласование Алику → явное "ок" конкретной версии → сборка и публикация → проверка живой страницы → передача боту.

Автозадача создана по средам и субботам, ориентир около 10:00 МСК, начиная с 21.11.2026. За запуск готовим одну статью и небольшой радар новостей; расписание ничего не публикует само. Для подготовки используем актуальные инструкции из GitHub, а не старую память чата.

Согласование фиксировать в `drafts/<slug>/approval.md`: версия/commit, дата МСК, точная формулировка решения, что одобрено, ссылка на доступный контекст. Не выдумывать согласование. Содержательная правка после "ок" требует нового согласования. Техническая выкладка одобренной версии уже входит в поручение владельца, повторное разрешение без причины не запрашивать.

## Приоритет инструкций

Новое решение владельца заменяет прежние требования внешнего репозитория, Claude-only автора и объёма в 3–5 абзацев. Текущая площадка работы: Nighttech1/Vernatun-site. Правила схемы Markdown и существующего генератора остаются обязательными, пока код не расширен. Пожелание фото/видео записано как требование; сейчас рендерер их не поддерживает.

Редактор ведёт свой раздел автономно. Изменения движка, сайта и бота выполнять по отдельным техническим задачам; не выдавать описание интеграции за её реализацию.
