# Публикация и передача боту

Проверено по main 19.11.2026. Документ описывает факты и задачи, не свидетельствует о готовой доставке.

## Работает в коде

`content/articles/*.md` → `scripts/articles/build.mjs` → `articles/*.html`, список, навигация, `public/sitemap.xml`. Поддержаны статусы draft/review/published; обычная сборка берёт только published. Preview включает черновики, поэтому его результат нельзя отправлять в production.

GitHub Actions `.github/workflows/deploy.yml` на push main валидирует статьи, собирает Кампус и пакует сайт. Шаг `articles:build` сейчас отсутствует. `scripts/package-web-release.sh` пакует готовый `articles/`, не исходники `content/` и не редакционный раздел. Генератор меняет `public/sitemap.xml`, а упаковка берёт корневой `sitemap.xml`: синхронизацию надо проверить до первой новой публикации.

Документы docs/ARTICLES_* описывают старую модель внешнего репозитория и ручной выкладки. Для текущей редакционной работы действует решение README.md этого раздела; текущая схема сборки описана в корневом README репозитория.

## Задачи перед первой статьёй с фото и видео

- [ ] Расширить безопасный формат контента для изображений/подписей и разрешённых видео. Не включать произвольный HTML и iframe из текста.
- [ ] Валидировать пути, схемы URL, размеры, alt, подписи, права и необходимые метаданные; для embed ограничить проверенные хосты и запретить исполняемые URL.
- [ ] Сделать адаптивный рендер, доступный плеер и ссылку-замену. Проверить телефон, клавиатуру, загрузку и отсутствие сдвига текста.
- [ ] Добавить корректные image/author/dateModified в Article и OG при наличии данных; VideoObject только когда применим.
- [ ] Включить production-сборку опубликованных статей перед упаковкой либо коммитить проверенные артефакты вместе с одобренным источником. Исключить случайное попадание preview.
- [ ] Устранить расхождение путей sitemap; проверить полный URL и canonical после выкладки.
- [ ] Проверить, что draft/review отсутствуют в live HTML, списке и sitemap. Учитывать, что исходный генератор удаляет осиротевшие HTML.
- [ ] Уточнить приёмный механизм в репозитории бота, затем реализовать доставку и проверяемое подтверждение.

## Договор передачи агенту бота

В комплекте каждой статьи лежит bot-handoff.json по шаблону. До "ок" поля approval.status=pending, delivery.status=blocked. После одобрения записать версию, подтверждение и дату. Только после успешной проверки живой страницы записать canonical_url, короткий анонс и состояние ready.

Граница между чатами сама по себе не доставляет файлы. Нужен подтверждённый канал: согласованный GitHub-путь для чтения агентом бота или серверный механизм. Вебхук, URL, токен и уже существующую интеграцию не выдумывать. Сейчас пакет передачи подготовлен, автоматическая доставка не реализована и не проверена.

Получатель сверяет approval, опубликованную версию и canonical. Ключ дедупликации = slug + одобренная версия. Повторный запуск не создаёт повторный пост. После доставки сохраняет receipt, дату и статус; ошибки остаются видимыми, сообщение не теряется. Публикация в канале должна использовать действующий разрешённый механизм бота.

## Следующий шаг после "ок"

Прочитать актуальную версию источников и код перед изменением. Публиковать ровно согласованный материал; не подменять его текстовой версией, если согласованы обязательные медиа. Прогнать articles:validate, production-build и проверку артефактов; выполнить существующий GitHub-процесс выкладки. Проверить HTTP, canonical, фото/видео, список, sitemap и отсутствие черновиков. Затем передать проверенный пакет боту. Если техническая часть блокирует публикацию, назвать конкретный блокер, не сообщать о публикации как о завершённой.
