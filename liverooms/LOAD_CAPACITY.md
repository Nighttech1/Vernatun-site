# Нагрузочный ориентир Vernatun Lounge (N комнат × M слушателей)

Документ фазы 7 P2. Это **ориентир после пилота**, не результат промышленного load-test.
Полный stress-тест фермы — отдельная задача; VPS/prod — только после явного «да».

## Зафиксированные цифры (пилот localhost, 2026-09)

| Среда | N комнат | M слушателей / комната | Одновременных publish (говорит) | Статус |
|-------|----------|-------------------------|----------------------------------|--------|
| Localhost Docker (dev LiveKit + coturn, Windows) | **3–5** | **8–12** | **2–4** одновременно | комфортный пилот |
| Localhost «потолок комфорта» | **≈8** | **≈15** | **≤6** | следить за CPU/packet loss |
| Будущий VPS (черновик, **не деплой**) | TBD после «да» | TBD | TBD | измерить на железе |

**Почему такие цифры:** пилот — учебные комнаты Кампуса, не массовый стриминг. Dev-диапазон UDP портов LiveKit узкий (`51000–51020`). Mute-by-default снижает число одновременных publish, что важнее сырого числа «слушателей».

## Критерии

| Уровень | Признаки |
|---------|----------|
| Комфортно | Dual-peer слышат друг друга; нет заметного jank UI; Grafana/Prometheus без постоянного CPU ~1.0; ICE ок |
| Предел | Рост packet loss / reconnect; задержки речи > ~400 ms; SFU watch → алерты в Owner Inbox |
| Стоп | SFU down алерт; диск/webhook storm; нельзя восстановить dual-peer без рестарта |

## Методика измерения (без полного load-test)

1. Поднять infra: `docker compose --profile metrics up -d` в `liverooms/infra/`.
2. Открыть Grafana http://127.0.0.1:3000 → дашборд **Vernatun LiveKit rooms**.
3. Открыть N комнат Кампуса (`/campus`), в каждой M вкладок/устройств (хотя бы 2 реальных peer с Unmute).
4. Зафиксировать в таблице ниже: N, M, publishers, CPU node, субъективное качество.
5. Записать дату и железо (ноутбук / VPS).

### Шаблон записи пилота

```text
Дата:
Железо / ОС:
N комнат:
M на комнату:
Одновременных Unmute:
Наблюдения (аудио / UI / Grafana):
Вердикт: комфортно | предел | стоп
```
