# План: автопубликация статей Claude-агентами (Вернатун)

**Статус:** спроектировано и реализовано в волне **W-72** (C-257/C-258/C-259),
прогнано локально, ждёт приёмки Клиента + «да» на VPS-деплой + внешний репо статей.
**Дата:** 2026-10-31.
**Тикеты:** `C-257` (движок), `C-258` (контракт агента), `C-259` (миграция + тест) — `memory/tickets/`.

## 0. Что изменилось после уточнений (2026-10-31)

- **Источник статей — внешний GitHub-репозиторий** (пользователь передаёт отдельно). Статьи
  складываются туда → оттуда попадают в сборку сайта. В коде это точка `ARTICLES_SRC`: по
  умолчанию `content/articles/` (для локального теста), в проде = путь к клону внешнего репо.
  Весь контракт (схема, CLI, гейт) от этого не меняется.
- **Агент, который пишет статьи, — в отдельном чате Claude.** Наша задача здесь — только
  **спроектировать и собрать систему** (движок + контракт), не писать контент статей.
- **Сейчас:** тестовая выкладка прогнана локально. **Потом:** после деплоя на VPS — повторный
  тест контракта уже на проде.

## 1. Цель

Дать нашим Claude-агентам возможность **самим готовить и выкладывать статьи** на сайт
`vernatunspeakclub.com` **по расписанию**, сохранив сайт полностью статическим и наши
командные правила (ревью Клиента, запрет prod без явного «да»).

Утверждённые решения (из обсуждения):

1. **Git-пайплайн + редеплой** — агент кладёт контент в репозиторий, генератор строит HTML,
   коммит, прогон deploy-скрипта. Никакого нового runtime-сервиса на VPS, нулевая новая
   поверхность атаки. Сайт остаётся 100% статическим для читателей.
2. **Черновик → апрув → публикация** — агент создаёт `draft`, человек подтверждает,
   только после этого статья собирается и уходит на сайт.
3. **Планировщик — Claude scheduled task** — расписание в Claude Code запускает агента,
   который пишет черновик и останавливается на запросе апрува.

«API» для агентов в этой модели — это **контракт контента + CLI-команды генератора**
(схема front-matter, `new` / `validate` / `build` / `publish`), а не HTTP-эндпоинт.

## 2. Как устроен раздел статей сейчас (факты)

- Список: [`articles.html`](../articles.html) → чистый URL `/articles`. Блоки `.magazine-row`
  с рубрикой (терракотовый eyebrow), заголовком и «Читать» — правятся руками.
- Статьи: отдельные файлы в [`articles/`](../articles) (`esli-stesnyaeshsya.html` и др.),
  чистый URL `/articles/<slug>` (nginx: `try_files $uri $uri.html …`, а `*.html` → 301 на без-`.html`).
- Шаблон статьи стабилен: `<head>` с canonical/description/шрифтами/Tailwind CDN/Alpine,
  `<div id="site-header">` + `/js/site.js`, `<article>` с eyebrow + `h1` + лид-абзац +
  блок `.space-y-4` абзацев + ссылка «Все статьи», `<div id="site-footer">`,
  `VernatunChrome.mountRest()`.
- Навигация: [`js/site.js`](../js/site.js) хардкодит пункт «Статьи» и список статей в дропдауне.
- Карта сайта: [`public/sitemap.xml`](../public/sitemap.xml) — раздел `/articles` есть,
  отдельных статей нет.
- Деплой: [`scripts/deploy_vernatun_to_vps.ps1`](../scripts/deploy_vernatun_to_vps.ps1)
  уже заливает `articles/`, `articles.html`, `js/`, `public/sitemap.xml`. **Доп. изменений
  в деплое не требуется** — генератор пишет ровно те артефакты, что скрипт уже выкладывает.

**Вывод:** добавление статьи сегодня = синхронное ручное редактирование 3–4 мест
(файл статьи, список, sitemap, навигация) с риском расхождений и mojibake
(есть `scripts/fix_utf8_mojibake.py` — кодировка уже кусала).

## 3. Целевая архитектура

### 3.1. Источник правды — контент-файлы

Новый каталог `content/articles/<slug>.md` — **единственный источник** статьи
(Markdown + YAML front-matter):

```yaml
---
slug: kak-nachat-govorit           # [a-z0-9-], уникален, = имя файла
title: Как начать говорить          # <h1> и <title>
category: Новичкам                  # терракотовый eyebrow + рубрика в списке
description: ...                    # meta description + og:description (<=160 симв.)
lead: ...                           # первый крупный абзац (text-lg)
date: 2026-10-31                    # сортировка списка (desc) + sitemap lastmod
status: draft                       # draft | review | published
author: claude-agent                # кто сгенерировал
---

Абзац тела в Markdown. Поддержка **жирного**, ссылок, списков,
подзаголовков — строго ограниченный безопасный набор.
```

`content/` **не выкладывается** на VPS (его нет в списке deploy-скрипта) — на сервер
уходят только собранные HTML. Черновики не видны публично до сборки.

### 3.2. Генератор — `scripts/articles/build.mjs` (Node, ESM)

Запуск через npm-скрипты (ниже). Минимальные зависимости: `gray-matter` (front-matter)
и `marked` (Markdown→HTML) — ставятся в devDependencies.

Задачи генератора:

1. Прочитать все `content/articles/*.md`, провалидировать.
2. Для каждой `published` статьи отрендерить `articles/<slug>.html` **точно по текущему
   шаблону** (один шаблон-функция, чтобы все статьи были единообразны): canonical,
   title, meta description, og-теги, JSON-LD `Article`, eyebrow=category, h1=title,
   lead, тело из Markdown, ссылка «Все статьи».
3. Пересобрать список в `articles.html` — блоки `.magazine-row`, сортировка по `date` desc.
4. Пересобрать пункты статей в навигации. Чтобы не редактировать живой JS хрупко,
   делаем **одно из** (решить при реализации):
   - **(реком.)** упростить дропдаун «Статьи» до одной ссылки `/articles`
     (новые статьи больше не трогают `site.js` вообще), **или**
   - вынести список статей в данные `js/articles-nav.js`, которые читает `site.js`, **или**
   -区 заменять содержимое по маркерам `/* ARTICLES:START */ … /* ARTICLES:END */`.
5. Добавить `<url>` каждой `published` статьи в `public/sitemap.xml` (по маркерам/пересборкой).
6. Писать строго **UTF-8 без BOM**; прогонять защиту от mojibake.

Режимы:
- `build` — рендерит только `published` (то, что уходит в прод).
- `preview` — рендерит и `draft`/`review` во временную папку для локального просмотра
  на `http://127.0.0.1:<port>` через `scripts/dev_server.py`.

### 3.3. CLI-контракт для агентов — `scripts/articles/cli.mjs`

Это и есть «API», который агент вызывает детерминированно:

- `articles new --slug <s> --title <t> --category <c>` — создаёт валидный черновик-скелет
  в `content/articles/<s>.md` со `status: draft`.
- `articles validate [--slug <s>]` — проверяет: обязательные поля, формат/уникальность slug,
  длины (title/description/lead), только разрешённый Markdown, отсутствие сырого HTML/скриптов,
  кодировку. Код выхода ≠ 0 при ошибке (для CI/расписания).
- `articles build` / `articles preview` — см. выше.
- `articles publish --slug <s>` — переключает `status` на `published` (**шаг апрува**,
  выполняется человеком или по явному подтверждению).
- `articles list` — таблица статусов.

npm-скрипты в `package.json`: `articles:new`, `articles:validate`, `articles:build`,
`articles:preview`, `articles:publish`.

### 3.4. Гейт апрува (черновик → публикация)

1. Агент создаёт `content/articles/<slug>.md` со `status: draft`, прогоняет `validate`,
   коммитит **в ветку** `article/<slug>` (не в `main`).
2. Агент собирает `preview`, даёт человеку ссылку на локальный предпросмотр и
   **останавливается с запросом апрува** (в духе нашего правила «нет prod без да»).
3. Человек смотрит, правит при необходимости, затем апрувит → `articles publish --slug <s>`
   (ставит `published`).
4. Только тогда: `articles build` → коммит собранных артефактов → деплой (§3.6).

### 3.5. Планировщик — Claude scheduled task

Расписание (напр. еженедельно) запускает агента со скиллом домашнего стиля:

- шаг 1: выбрать тему из бэклога идей (`content/_ideas.md`), написать черновик по схеме §3.1,
  `validate`, закоммитить в ветку, **запросить апрув** — и на этом расписание останавливается.
- шаг 2 (после апрува человеком): `publish` → `build` → деплой.

Расписание **не публикует само** — оно доводит до готового черновика и зовёт человека.
(Вариант автопубликации сознательно отклонён на этапе решения.)

### 3.6. Деплой на VPS

Без изменений в `deploy_vernatun_to_vps.ps1`: он уже выкладывает `articles/`,
`articles.html`, `js/`, `public/sitemap.xml`. Последовательность:

```powershell
. ".\vps door\load-ssh-env.ps1"
npm run articles:build
# git add -A && git commit -m "articles: publish <slug>"
powershell -File scripts\deploy_vernatun_to_vps.ps1
```

Health-check уже встроен в скрипт (`curl` по 127.0.0.1:85 и https://vernatunspeakclub.com/).
После деплоя — проверить `/articles` и `/articles/<slug>` вручную/пробой.

### 3.7. Тесты и guards (роль Тестер)

- `articles validate` зелёный на всех файлах.
- Снапшот-проба (по образцу `scripts/*.mjs` + `dev_server.py`): страница статьи содержит
  canonical/title/description, лид и тело, ссылку «Все статьи»; список содержит новую статью;
  sitemap валиден; нет mojibake; файл лежит как `articles/<slug>.html` (совместимость с
  clean URL nginx).
- regression-guard: пересборка не ломает 3 существующие статьи (их тоже переносим в `content/`).

## 4. Интеграция с командной моделью

По нашим правилам (`docs/AGENT_TEAM_BOOTSTRAP.md`):

- Клиент/Оркестратор заводит тикет `memory/tickets/C-xxx-articles-autopublish/` + строка в `_index.md`.
- Архитектор: `architect-spec.md` + `chain.md` **до кода** (этот документ — основа спеки).
- Новый скилл домашнего стиля статей (голос клуба: тёплый, не-учебник, как 3 текущие статьи) +
  схема контента — в `knowledge/area_*` / `.cursor/skills`, чтобы scheduled-агент писал on-brand.
- prod/VPS — только после приёмки Клиента и явного «да».

## 5. Этапы работ (chain)

| # | Шаг | Артефакты | Роль |
|---|-----|-----------|------|
| 1 | Тикет + architect-spec + chain | `memory/tickets/C-xxx/...` | Клиент/Архитектор |
| 2 | Схема контента + перенос 3 статей в `content/articles/*.md` | `content/`, `_ideas.md` | Бекендер |
| 3 | Генератор `build.mjs` + шаблон + список + sitemap + навигация | `scripts/articles/`, `package.json` | Бекендер |
| 4 | CLI `new/validate/publish/list` | `scripts/articles/cli.mjs` | Бекендер |
| 5 | Скилл домашнего стиля + контент-гайд для агентов | `knowledge/`/`.cursor/skills` | Архитектор |
| 6 | Тесты/guards (валидация + проба на localhost) | `scripts/*.mjs`, `guards.md` | Тестер |
| 7 | Прогон: агент пишет тестовый черновик → preview → апрув | ветка `article/<slug>` | Клиент |
| 8 | `build` + коммит + **деплой на VPS** + проверка `/articles/<slug>` | VPS | Деплоер |
| 9 | Claude scheduled task (ideate→draft→запрос апрува) | расписание | Оркестратор |

Шаги 2–5 частично параллелятся на непересекающихся путях; деплой (8) — последний, после апрува.

## 6. Риски и решения

- **Кодировка (mojibake).** Генератор пишет UTF-8 без BOM; валидатор и проба ловят.
- **Хрупкое редактирование `site.js`.** Упростить дропдаун статей до одной ссылки (реком.)
  либо вынести данные/маркеры — не редактировать живой JS регулярками наугад.
- **Инъекции в контент.** Markdown-рендер с белым списком, без сырого HTML/`<script>`; экранирование.
- **Публикация сырого.** Обязательный гейт апрува; расписание само не публикует.
- **Расхождение источников.** Единый источник = `content/*.md`; список/sitemap/навигация только генерятся.
- **Откат.** Всё в git (`before_sha` в `decisions.md`); redeploy предыдущего коммита возвращает сайт.

## 7. Решения реализации (закрыты в W-72)

- Язык генератора: **Node .mjs, zero-dependency** (свой парсер front-matter + Markdown-сабсет).
- Навигация/список/sitemap: **маркеры-регионы** (`ARTICLES:START/END`) — безопасная правка.
- Обложки/изображения: v1 — текст (как сейчас); картинки — отдельной итерацией.

## 8. Открытые входы (ждём от пользователя)

- **GitHub-репозиторий статей** — URL + как получаем доступ (клон/submodule/CI-шаг), чтобы
  навести `ARTICLES_SRC` на него и прогнать контракт на проде.
- **Явное «да» на VPS-деплой** (правило: нет prod без согласования).
- Частота расписания (Claude scheduled task) и источник тем (бэклог идей).
