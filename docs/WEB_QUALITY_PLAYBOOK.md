# Качество сайта: процедуры для команды

Дата: 19.11.2026. Это проектные процедуры, а не утверждение о пройденных проверках.

## Ассеты — Frontend + Motion

1. Собрать manifest: исходник, права/согласие на фото, назначение, размеры, вес, мобильная версия, poster, alt.
2. Для фото подготовить WebP/AVIF и fallback, srcset/sizes; задать width/height или aspect-ratio.
3. Hero должен показывать текст и poster до загрузки видео. Проверить отключённое видео и reduced-motion; не прятать запись на встречу за заставкой.
4. Выбрать размер hero по реальной ширине экрана; не отправлять desktop-видео телефону без оценки трафика.
5. Не lazy-load LCP-изображение; lazy-load материалы ниже первого экрана.
6. pause() видео вне viewport и при скрытой вкладке; при отказе play() оставить poster. WebGL: один canvas, pause offscreen, dispose, fallback при context loss.
7. Записать before/after веса и сетевой waterfall; предложение по весу ниже — проектный бюджет, не универсальный стандарт.

Начальные бюджеты для следующего прототипа: мобильный poster <=200 KB; остальные критические изображения суммарно <=500 KB; дополнительный JS motion <=80 KB gzip. Видео и WebGL грузить после базового контента. Превышение обсуждать по измерениям, а не скрывать.

## SEO — Frontend + Tester

Для /, /schedule, /articles и примера статьи проверить реальный HTTP URL, title, description, canonical, OG с абсолютным image URL, lang, h1, indexability, sitemap и robots.
Redirect-страницы учитывать отдельно: не требовать от них полного набора метаданных конечной страницы.
Для Campus не считать один SPA shell доказательством корректных метаданных всех маршрутов. Сначала решить, какие страницы должны индексироваться; admin и личные/служебные комнаты не включать в sitemap.
Структурированные данные Event добавлять только с подтверждёнными датой, местом и условиями. Не генерировать отзывы и рейтинги.
Результат — таблица URL / HTTP / title / canonical / OG / indexability / найденная проблема.

## Accessibility — Tester + независимый Client

Использовать a11y-debugging, если доступен Chrome DevTools MCP. При отсутствии MCP выполнить доступные ручные проверки и записать ограничение.
Tab/Shift+Tab, видимый focus, skip-link, Escape, возврат фокуса после модалки; кнопки доступны с клавиатуры и touch.
Проверить контраст текста поверх видео на нескольких кадрах, zoom 200%, доступные имена icon-кнопок, labels, ошибки форм.
Проверить 390 и 412 px, отсутствие горизонтального скролла, safe-area, длинные русские и армянские строки.
Не объявлять соответствие WCAG по одному Lighthouse score; автоматическая проверка не покрывает все критерии.

## Motion и производительность — Motion + Tester

Для каждого эффекта: смысл, trigger, duration, easing, reduced-motion, mobile fallback, cleanup.
Сначала CSS/WAAPI. GSAP только для сложной хореографии; WebGL только после сравнения с видео/CSS.
Снять cold-load trace и три сопоставимых прогона на одинаковых CPU/network настройках; сохранить медиану и исходные отчёты.
Цель: LCP <=2.5 s, CLS <=0.1; INP <=200 ms оценивать по полевым данным при их наличии. Лабораторная трасса не доказывает полевой INP.
Проверить память после повторного входа/выхода из Campus, отсутствие лишних listeners/RAF и влияния marketing motion на аудио.

## Preview и доказательства — Deployer + Client

Текущий main автоматически деплоится. Для разработки использовать feature branch + локальный preview; публичная PR preview-среда пока не реализована.
Static: python scripts/dev_server.py. Campus: npm ci и npm run dev в liverooms/web. Перед release: npm run articles:validate из корня и npm run build из liverooms/web.
Существующий test:lobby уже есть; расширять его. Не заменять ручную проверку двух аудиопиров DOM-asserts.
Артефакты в memory/waves/<wave>/evidence/: before/after desktop 1440, mobile 390/412, reduced-motion, сценарии/console/network, performance summary, список открытых P0/P1.
На скринах зафиксировать URL, commit, viewport и состояние. Для видео hero дополнительно короткая запись прокрутки.
Без browser runtime статус визуальной приёмки — pending. Не заменять его утверждением по HTML.
