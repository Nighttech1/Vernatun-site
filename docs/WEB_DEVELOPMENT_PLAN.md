Актуализация: 19.11.2026. Дополняет liverooms/DEVELOPMENT_PLAN.md; исторические [x] не являются повторной приёмкой production.
Задача пользователя сейчас — усилить команду; нижеследующие продуктовые работы ещё не выполнены.

## Волна T — подготовка команды

- [x] Разобрать видео и существующую библиотеку.
- [x] Выбрать и включить в репозиторий 5 официальных skills с лицензиями и фиксацией source commit.
- [x] Добавить входные инструкции для Codex/Claude/Cursor и профиль Vernatun.
- [x] Подготовить MCP-конфигурацию и процедуры качества.
- [ ] Запустить MCP в целевой среде и выполнить реальные screenshot/trace вызовы.
- [ ] Независимо принять изменения команды и объединить PR.

## Волна V1 — baseline и ассеты, P1

Ответственные: Архитектор → Frontend/Motion → Tester → Client.
- [ ] Создать ticket + architect-spec + chain с точными paths.
- [ ] Снять baseline главной, расписания, статей и Campus, desktop/mobile.
- [ ] Составить asset manifest; проверить hero video/poster, веса, загрузку шрифтов.
- [ ] Оценить замену runtime Tailwind CDN на собираемый CSS для статического сайта.
- [ ] Проверить видимость контента при ошибке JS/reveal; проектные guards для CTA и меню.
- [ ] Добавить mobile/reduced-motion проекты в существующую Playwright-конфигурацию, сохранять trace при ошибке.
Выход: воспроизводимые измерения и список проблем; не переписывать существующую тему без baseline.

## Волна V2 — первый экран уровня референса, P1

Ответственные: Архитектор → арт-дирекция/Frontend → Motion → Tester → независимый Client.
- [ ] Подготовить 2 визуальных направления внутри бренда и выбрать одно по понятности приглашения в клуб.
- [ ] Создать storyboard: первый экран → атмосфера живого общения → формат/уровень → ближайшая встреча → запись.
- [ ] Сделать вертикальный срез hero + одна следующая секция с реальными разрешёнными ассетами.
- [ ] Настроить типографику RU/HY, переходы, доступный CTA; проверить desktop/mobile и отсутствие видео.
- [ ] Только после измерений решить, нужен ли WebGL; предусмотреть статичный fallback.
Выход: Client видит before/after, запись motion, mobile и performance evidence. Красота не заменяет рабочую запись.

## Волна V3 — доверие, расписание, поиск, P1

Ответственные: Frontend → Backend только если нужен новый контракт → Tester → Client.
- [ ] Проверить путь новичка: уровень языка, адрес, цена/условия, ведущий, дата, запись.
- [ ] При отсутствии подтверждённого события показывать честное пустое состояние; расписание брать из согласованного источника.
- [ ] Проверить SEO/OG/canonical/robots/sitemap по процедуре.
- [ ] Если появляется форма: server-side validation, защита от повторных отправок, понятный success/error, лимиты и хранение данных.
- [ ] Настроить минимальные события воронки с согласованной аналитикой; не отправлять личные данные.
Выход: проверяемая запись на встречу и корректная выдача ссылок.
